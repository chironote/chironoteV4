# iOS recording and dictation

`RecordingManager.jsx` owns the existing iOS microphone, chunk upload and WebKit finalization lifecycle. Native iOS is identified through Capacitor platform identity, with a web iPhone/iPad user-agent fallback; the shared result controls MIME selection and lifecycle even for Mac-style iPad user agents. iOS prefers supported audio/webm;codecs=opus, falling back to video/mp4 on older devices. A 1000ms timeslice retains every nonempty piece for the recorder cycle and assembles one complete Blob using the recorder MIME type at onstop. Pieces are never uploaded independently. Stop transactions wait for delayed dataavailable/onstop, rotate once on foreground and suspend the rotation timer in background. Discard cancels only that recording; unmount cancels all work. WebM recordings match existing WebM upload labels; legacy MP4 fallback keeps the previous labels.

Finalized Blobs stay in the existing in-memory queue until S3 and SQS acknowledge them. Upload and dispatch have separate stages, so a lost SQS response retries submission with the same path/FIFO identity without re-uploading. Transient failures use exponential jitter (1-second initial ceiling, 60-second cap, 250ms minimum delay); HTTP400 throttling/expired-token/timeouts remain retryable. Advancing bytes reset the 120-second upload watchdog, including after SDK multipart progress drops during internal retries. Dispatch aborts after 60 seconds. Cancellation waits for the SDK task to settle before another attempt. Timers recover without an online event; connectivity hints and Retry cannot create a second worker. Persistent authorization/validation errors retain a blocked item visible both in the shell and waiting dialog for explicit retry. Pending audio is not restart-safe; keep the app open.

Record next appointment returns to capture settings while earlier work continues. Queue order is preserved within each recording; a failed regular chunk holds its own final. Starting B never invalidates A. Each recording owns its note subscription, stream, immutable capture and existing timeout policy. Background A still generates and opens its authoritative saved-note/history path, while clipboard/popup/spinner effects follow presentation ownership. Opening new settings detaches the old presentation before B starts. NoSleep has a separate capture owner, released even if the user never successfully starts B. Discarding B cannot cancel A. There is no new storage layer or native network plugin.

WebKit data is retained per recorder cycle until onstop assembles all bytes and commits regular/final classification; Stop between the two delayed events still submits one final containing the complete segment. The next cycle starts with an empty buffer. Start exposes microphone startup/stop-settling status separately from backlog, with equivalent final-event fencing for non-iOS paths in this client. Closing during startup cancels its capture. Credit results are scoped to an accepted capture session and component request; a late A denial/error cancels only A's remaining work, reports that earlier failure and cannot discard B or show a credit popup over B. Guarded/no-op Starts neither run another credit lookup nor invalidate an accepted check. Credit-denial policy is unchanged.

Queue auth reads time out after 60 seconds. Amplify has no abort handle for that read; late results are fenced and cannot resume an expired queue attempt. Dispatch-only retries refresh once. A successful S3 result racing cancellation still advances to dispatch-pending. Identical FIFO IDs are retained after a lost acknowledgement, but FIFO deduplication is time-limited; client tests do not prove backend exactly-once processing or billing.

`useNoteGeneration.js` owns transcript subscriptions and note streaming. RecordingManager forwards generation status/errors and authoritative saved-note identity to AppShell; an earlier saved note refreshes history without replacing the current clipboard. EOF previews do not become saved-note identity. RecordingManager.test.js and useNoteGeneration.test.jsx cover mocked transport/session ownership alongside delayed-WebKit lifecycle regressions. These do not establish physical-device reliability or backend billing behavior.

`Recording.jsx` uses compact PatientCapturePicker: existing patient implies follow-up, new name implies initial exam, Re-Exam remains explicit, selected patient collapses to name and reset, and history is automatic. Capture metadata and settings are snapshotted before async startup.

`Dictation.jsx` retains the native token/AudioWorklet pipeline and receives optional onDictationStart/onDictationTextUpdate/onDictationStop callbacks. The shell snapshots the selected range, inserts revised partial transcripts without replacing surrounding text, and never changes clipboard text just to indicate loading. Legacy callers without insertion callbacks keep their previous replacement contract. Pure insertion tests cover surrounding-text preservation and repeated revisions.

This folder also owns recording controls, transcript status, permission explanations and credit dialogs. No live provider/device behavior is established by source tests. Source: cap-ios 2326d34 lifecycle, prod142383e compact capture, 2026-10-11 callback wiring.

The recording lifecycle test isolates unrelated PDF delivery imports so native plugin registration cannot interfere with its real microphone/WebKit timing cases. The dictation insertion suite supplies stable external-service/NoSleep doubles that survive CRA resetMocks, while executing the actual Dictation hook and media setup/callback path.

Recording.css scopes its New Note flex/width rules to `.recording-dialog`, preventing those recording styles from resizing the Clipboard toolbar. Recording and dictation lifecycle behavior is unchanged.


Exam Layout remains visible for new and unassigned capture: new patients force a checked, disabled gray checkbox and initial-exam metadata; unassigned visits use the editable manual choice. Existing patients retain follow-up/Re-Exam semantics. Manual exam preference is stored separately in `unassignedExamLayout` (initially seeded from legacy `noteSettings`) so a forced capture cannot become manual intent after clearing or reopening. PI is independent. Effective `noteSettings` are written synchronously before RecordingManager freezes its separate settings/visit snapshots; backend ICD rules are unchanged.

A typed, unselected name is checked across matching directory pages, then Start Recording opens the existing PatientDialog confirmation after the Exam/PI options. Create patient & record starts from its click; Record without a patient clears identity, injury and initial-exam linkage while preserving the preceding Exam/PI choices. Duplicate/error feedback retains the draft. Lookup preparation is invalidated on name edits, selection, clear and unmount. Blank unassigned and feature-disabled paths start directly. This is frontend source only; no native build or deployment is implied.

### Recovered saved results

The current V4 Capacitor client's per-capture sessions remain independent. A
background recovered completion refreshes history without changing the foreground
clipboard. Foreground completion installs the exact saved body/version as its
clean editable baseline. Opening another Patients visit is held while generation
owns the clipboard. No native project or bridge change is included.

Stream controls are parsed incrementally. NOTE_RECOVERED retrieves the authoritative saved body/version; true errors preserve a preview with unconfirmed persistence. Cancellation cannot block saved-result retrieval. See the recording knowledge concept and regression tests.
