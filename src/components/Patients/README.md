# Patient components

Desktop web has persistent Save; the clipboard remains local-edit/copy only on mobile and adds no mobile Save control. The Patients route owns profiles, source diagnosis display and PDF selection. Settings owns Configure Signature.

All clinical requests go through `../../services/patientNotes.js`; server owner verification and conditional Save are authoritative. PatientsPage opens an exact getSavedNote result in the existing clipboard through AppShell, including source-note links. There is no second clinical editor. VisitDetailsDialog owns patient assignment, service/injury dates, visit type, label, profile suggestions and generation retry; PDF date correction uses this metadata-only dialog too.

useClipboardSave binds the exact timestamp/version/body and a stable request ID. Explicit Assessment code changes on every visit type show the full code/description list and Confirm and save, without new/continuing/resolved controls. Existing status values remain internal; additions default to new. Missing/ambiguous descriptions still require input. Approval atomically saves body/list and establishes a diagnosis source without a Re-Exam. Source precedence follows visit chronology; other saved visits remain unchanged. Ordinary saves omit diagnosisCodes and retain server reconciliation. Editing invalidates approval; conflicts preserve the draft.

PatientDialog traps keyboard focus and restores the opener. useDraftGuard registers memory-only drafts and prevents transitions during save; draftNavigation serializes guarded transitions. CSS supports narrow layouts and visible focus.

Do not add a persistent PHI draft cache, infer patient identity from labels, substitute preview EOF for a saved result, or enable new mobile Save controls. See the repository patient-notes knowledge concept for gates and validation.

## Patient UI correction

PatientCapturePicker skips empty searches and defaults to patient selection only. The recording search has a Patient Name legend and Select Existing Patient, Add New or Leave Unassigned placeholder, with no separate Unassigned status or duplicate helper text; showVisitDetails is enabled explicitly by VisitDetailsDialog. Recording collapses selected patients to a name-only panel with × reset, defaults existing selections to followUp and newly entered patients to initialExam, and always includes saved history. Re-Exam is controlled by Recording; full visit fields and explicit history choice remain in Patient and visit details. useClipboardSave normally sends the body, timestamp, loaded version and stable request ID; only explicitly approved diagnosis changes add a structured list. Required review stays in the clipboard. History retains the original note/transcript ContentPopup; its patient name opens ReassignPatientDialog for association corrections. PatientsPage owns profile and visit metadata editing; normal diagnosis summaries use neutral product cards and warnings are reserved for actual review requirements. SignatureSettings uses the existing Settings card and displays only the last four NPI digits outside its edit dialog. PatientDialog reuses ProductDialog header/body styling while retaining its scoped keyboard trap.


Add New checks all matching directory pages before selecting a new capture identity. An existing normalized name produces a gentle inline message and preserves the search/results for selection. Lookup failure preserves the name and offers retry; changing the search invalidates an in-flight check. This is a capture-time UX guard, not a server uniqueness constraint.

ReassignPatientDialog loads the exact saved version and offers an existing/new patient picker with Re-Assign and Cancel. The backend copies the destination patient's latest effective codes and synchronizes coded Assessment entries atomically. A missing/unknown list clears former codes. Non-diagnosis prose, transcript and date/type remain. The copied snapshot keeps destination provenance as carriedForward; reassignment does not establish a new source or create review flags. Permanent-deletion acknowledgment and stale-version protection remain. Requires the coordinated PatientNotesApi release before website publication. PatientDialog consumes Escape even while busy.

New assignment requests include copyPatientDiagnoses=true. Older clients retain their existing review-first behavior; an old backend rejects the new field before writing. Resolved codes stay in internal snapshots but are omitted from displayed/copy-to-Assessment lists. Clipboard confirmation preserves hidden resolved entries; explicitly adding one back to the note restores it to the visible list without a status choice.

Patient deletion uses DeletePatientDialog with a fresh server summary and explicit permanent-deletion checkbox. updatePatient action=delete runs resumable batches; failures keep the dialog retryable, and in-progress directory entries contain only a generic label. Reassignment requires warning acknowledgment before deleteEmptyPatient; the server counts incomplete as well as complete records and atomically removes the original profile/name claim only when no other record remains. Export lists all blocking requirements and displays progress/errors beside Create PDF. Development now has the same public endpoint defaults as production; restart npm start after changing environment files.
