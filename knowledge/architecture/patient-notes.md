# Patient-linked saved notes

The production API cutover and authenticated synthetic acceptance are complete. The AppSync clinical-write guard and patient service flags are enabled; the feature-enabled website build remains unpublished for the existing owner-operated publish step. Four conspicuously fictional patients and seven visits passed the live workflow checks, including one synthetic WAV through transcription, note generation, save/edit/reassignment/re-exam/retry paths, and PDF export. The existing publication step and post-publication live microphone/screen review remain outstanding; physical iPhone/Android and native/extension acceptance are separate. Clinical prompt changes remain deferred. See [verified cutover and acceptance evidence](../operations/patient-infrastructure-release.md). Desktop web has persistent saved-note Save; the Patients editor is read-only with Copy on mobile and has no mobile Save control. The Patients route owns profiles, per-visit diagnosis display, source diagnosis summary and PDF selection. Settings owns Configure Signature.

`REACT_APP_PATIENT_NOTES_ENABLED=true` exposes patient/history features. `REACT_APP_PATIENT_CAPTURE_ENABLED=false` independently stops new patient capture without hiding saved-note tools. The capture picker supports typed existing/new patient lookup or an unassigned visit and an explicit no-history choice. Recording supplies local service date and automatic first-visit resolution without showing date/visit fields; optional injury date and explicit visit type remain editable in Patients. Patient metadata is captured once outside generic noteSettings. Microphone acquisition begins from the gesture before authentication/eligibility network waits. Cancelled permission requests and old stream completions cannot attach to a newer recording. Language preferences are retired; clients send auto and the server retains the installed-client adapter.

`src/services/patientNotes.js` sends signed access tokens to the website-owned AWSJSON operations. Names use a short-lived in-memory owner-keyed cache. Clinical drafts are memory-only and never enter localStorage, analytics or URLs. The authenticated workspace remounts on principal change; sign-out/unmount clears it. `src/components/Patients` owns the picker, current patient name, saved-note editor, metadata and draft guards. Historical row titles split the current directory name from visitLabel, retaining noteLabel only as a legacy fallback.

Desktop Save binds the exact note timestamp/version and draft to an owner-verified conditional server operation. Save failure, conflict or ambiguous diagnosis keeps the draft. The per-visit diagnosis editor can correct an existing code by replacing exact whole-code tokens in the note; the clinician reviews the resulting note preview and structured `diagnosisCodes` are saved atomically with that body. It never infers a new diagnosis or appends narrative, and the client sends `diagnosisCodes` only after an explicit correction. Codes display `new`, `continuing` or `resolved` status. AI diagnosis-state reconciliation is limited to notes classified `exam:true` whose note label is not `New Patient`; the visit-type picker is a separate field and does not establish that gate. Navigation prompts Save and continue / Discard changes / Keep editing; browser close uses beforeunload. Save does not regenerate prose, charge hours or rewrite later visits. Generation EOF is not a saved acknowledgment: retrieve the completed server note, preserve rejected output as a preview, and show a separate error. Native/mobile corrections remain local unless saved later on desktop. Profile suggestions are explicit accept/dismiss actions and become stale after body edits.

Web export reads the complete strong owner inventory (not the recent-history window), deduplicates pages, preserves selection, checks saved service dates/injury-date conflicts/review acknowledgment and sends saved keys only. The separate server PDF owns note/profile/signature reads and rendering. Configure Signature saves only Name/NPI on UserSubscription. The configured export endpoint must be HTTPS.

The October 10 coordinated cutover installed the additive schema/GSI and Cognito+IAM resolvers, dedicated API/generator/retry roles and queues, guarded body writers, protected retention, the Decisions re-exam classifier, and compatible audio/generator publication paths. Automatic cleanup is retired and the legacy SQSDispatcher mappings remain disabled; in-flight dispatcher invocations were allowed to drain for 300 seconds, while queue messages were preserved/quarantined rather than purged. The live API guard is `PATIENT_WRITES_GUARDED=true`; never disable it or restore an old body writer after clinician edits exist. Authenticated acceptance passed across four fictional patients and seven visits: real synthetic audio reached transcription and note generation, saved-note and diagnosis corrections persisted, stale writes conflicted safely, retry and reassignment behaved as expected, re-exam codes reconciled, and the exported PDF matched saved note text. Website publication remains owner-operated.

The existing Amplify production API stack update completed; read-only verification confirmed the Notes table identity and key were preserved, the patient GSI is active, and Notes Retain/UpdateReplacePolicy, deletion protection and 35-day PITR remain in force. The current runtime audit confirms the strict AppSync guard and intended retry mappings; both legacy dispatcher mappings remain disabled. The feature-enabled web build is still unpublished. The deployed generator uses the preserved clinical prompt; only the approved re-exam diagnosis classifier and speaker-role integration changed model-facing behavior. Monthly cleanup remains retired.

The source-managed API `override.ts`, generated by installed Amplify CLI 12.12.6, makes the existing Notes table retain on deletion/replacement, enables deletion protection, and preserves PITR. It keeps the Notes logical ID, physical-name expression, owner/timestamp key and patient GSI unchanged. Install pinned backend dependencies from `amplify/backend/package-lock.json`, then use `amplify build`; `api gql-compile` alone does not apply overrides. The custom Patients table already has Retain policies and recovery protection. The completed backend update and live Notes/Patients protection settings were verified in the installation evidence.

The initial additive installation temporarily used API environment `PATIENT_WRITES_GUARDED=false` to preserve legacy writers. That was a historical compatibility stage only. The current source override and deployed API set it to `true`, with compatible generator/audio/retry code installed and legacy dispatcher mappings disabled. In-flight dispatcher invocations were allowed to drain for 300 seconds; queue messages were preserved/quarantined, not purged. Do not disable the guard after clinician saves exist.

Local validation includes mocked unit tests and feature-enabled production builds. Live authenticated acceptance used fictional release fixtures and covered audio/transcription, generation, Save/reload, exact-code correction, stale conflict, generic-write guard rejection, retry idempotency, reassignment, re-exam classification and signed PDF export. The PDF text was checked against the saved synthetic notes and all pages were visually reviewed. These results do not establish clinical-quality approval or every-device coverage. A real microphone smoke test and live patient-screen review remain after website publication; actual iPhone/Android permission, background, rotation and auth checks and provider language accuracy/latency review remain separate follow-up work.
