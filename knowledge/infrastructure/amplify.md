## Patient release recovery policies and live guard

The October 10 API cutover completed against the existing Amplify production stack. The website remains unpublished. The first authenticated synthetic capture succeeded; remaining workflow acceptance is pending. See [verified release evidence](../operations/patient-infrastructure-release.md) for stack status, preserved resources, recovery protections and release boundaries.

`api/chironotev4/override.ts` is the source-managed model override created by the installed Amplify CLI 12.12.6. It retains the existing Notes table on stack deletion/replacement, enables table deletion protection, and keeps PITR enabled. Run `npm ci` from `amplify/backend`, then run `amplify build` from the repository root. The installed CLI's `api gql-compile` command compiles the schema without applying resource overrides. Likewise, `amplify build api chironotev4` is not recognized by this binary; use `amplify build`. Review the generated Notes table's identity/key/index and both Retain policies before any backend push; generated build files are not the editing source.

The override sets AppSync `PATIENT_WRITES_GUARDED` to the string `true` for the completed cutover. Only the exact value `false` bypasses the two post-auth clinical-write guards; owner authentication still runs. Missing or any other value enforces the guards. The earlier `false` compatibility setting was temporary and is no longer the source or live value. The read-only post-push check confirmed the processed API environment and active create/update post-auth templates enforce the guard. Never restore `false` after clinician saves exist.

The backend lockfile pins TypeScript 5.9.3 and cli-extensibility-helper 3.0.33. Explicit TypeScript libraries support the resolved CDK declarations. Local synthesis verified Retain/Retain, enabled PITR/deletion protection, and the API guard variable. Six AWS mapping-template evaluations verified legacy body writes pass only under explicit `false`; these tests did not mutate records. The post-cutover table identity/protection and guard evidence is summarized in [the October 10 release record](../operations/patient-infrastructure-release.md).

The AWS [API resource override guide](https://docs.amplify.aws/gen1/react/build-a-backend/graphqlapi/modify-amplify-generated-resources/) documents the model-table accessor.
